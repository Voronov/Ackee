# k6 benchmark: v1.0 (MongoDB) vs v2.0 (ClickHouse)

Date: 22.09.2026. Host: Apple M4 Pro (14 cores, 48 GB), Docker Desktop (7.65 GB limit per container),
MongoDB 7 and ClickHouse 26.8 in containers, Node 24, k6 0.x in Docker over `host.docker.internal`.

Scripts: `write.js` (30 VU, `createRecord`), `report.js` (10 VU, `views` DAILY/UNIQUE limit 30 and
`referrers` TOP/WITH_SOURCE LAST_30_DAYS), driver `run.sh`. Raw k6 summaries in `results/`.

Datasets, 60 days of synthetic traffic from `scripts/seed-records.js`, migrated to ClickHouse 1:1:
1M domain `49c3041d…`, 10M domain `25036c29…` (30-day window holds 5.03M records — the LR-1 profile).
Both stores hold the same rows; ClickHouse totals verified against MongoDB after every migration.

## Reports, 10 VU, 30 s

| Dataset | Report | MongoDB + compound index | ClickHouse | Gain |
|---|---|---|---|---|
| 1M | views 30d (unique) | p95 **4.47 s**, 2.7 req/s | p95 **0.155 s**, 101 req/s | **29×** p95, 37× throughput |
| 1M | referrers 30d | p95 **3.28 s**, 3.5 req/s | p95 **0.159 s**, 90 req/s | **21×** p95, 26× throughput |
| 10M | views 30d (unique) | **no request finished in 90 s** (0 req/s) | p95 **1.32 s**, 11.5 req/s | from unusable to usable |
| 10M | referrers 30d | **no request finished in 90 s** (0 req/s) | p95 **1.61 s**, 9.9 req/s | from unusable to usable |

Single request, no concurrency, 10M:

| Report | MongoDB + index | ClickHouse |
|---|---|---|
| views 30d unique | **> 300 s** (hit the client timeout twice) | 0.18–0.20 s warm, 1.69 s cold |
| referrers 30d | **> 300 s** (client timeout) | ~0.9 s |
| views 30d total (index-covered) | 29–30 s | 0.35 s warm, 2.2 s cold |

`views TOTAL` is the case LR-1 called "index-covered": MongoDB still needs 29 s, because the compound
index removes the document fetch but not the 5M-key scan and grouping. `views UNIQUE` also filters on
`clientId`, which the index does not carry, so MongoDB falls back to fetching 5M documents — hence > 300 s.

Direct SQL on 10M (no GraphQL layer): 0.29 s with `FINAL`, 0.17 s without — `FINAL` costs ~65 % here
(3 active parts) and is required for correctness, since it collapses touch and anonymise versions.

## Writes, 30 VU

Alternating runs on the same warm system (20 s each, two rounds), 10M dataset:

| Mode | req/s | p95 |
|---|---|---|
| `mongo` (v1.0 path) | 869 / 986 | 66 / 59 ms |
| `clickhouse` (writes to MongoDB **and** ClickHouse) | 599 / 682 | 95 / 89 ms |

Dual writes cost ~30 % throughput on this dataset: every `createRecord` additionally reads the visitor's
previous records for the anonymise mirror and buffers a ClickHouse row. Isolated earlier runs showed
2360 req/s (1M) and 1300 req/s (10M) for the ClickHouse mode — those numbers were measured on a less
loaded system and are not comparable with the MongoDB baseline; only the alternating runs above are.

Error rate was 0.00 % in every run; all checks passed.

## How to reproduce

```sh
cd bench
./run.sh <label> http://host.docker.internal:<port> <domainId> <token> 30s   # write + both reports
SKIP_WRITE=1 ./run.sh …                                                      # reports only
```
Server in the ClickHouse mode: `ACKEE_EVENT_STORE=clickhouse ACKEE_CLICKHOUSE_URL=http://localhost:8123 ACKEE_PORT=3100 npm run server`.
Token: `createToken` mutation with the credentials from `.env`.
