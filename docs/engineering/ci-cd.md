# CI/CD

Кожна зміна потрапляє в `develop` лише через pull request, а PR зливається лише з зеленим CI.
Тут описано, що саме перевіряється і як версія доходить до сервера.

## Перевірки на кожен push і PR

Файл `.github/workflows/test.yml`.

| Job              | Що робить                                                                                    | Чому                                                      |
| ---------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Test             | `npm run build:pre`, потім `npm test` (ESLint, Prettier, AVA) на Node 24 і 26, Linux і macOS | Linux – там працює образ, macOS – там пише команда        |
| Coverage         | `npm run test:coverage`, пороги в `.c8rc.json`                                               | Падіння покриття нижче порогу – це регресія, а не шум     |
| Dependency audit | `npm audit --omit=dev --audit-level=high`                                                    | Висока вразливість у тому, що їде в образ, зупиняє збірку |
| Docker image     | Збирає образ і перевіряє, що він стартує поруч із MongoDB                                    | Образ, який збирається, ще не означає образ, який працює  |

Окремо `.github/workflows/codeql.yml` запускає статичний аналіз CodeQL, а Dependabot
(`.github/dependabot.yml`) щотижня відкриває PR з оновленнями залежностей.

## Як запустити те саме локально

```
npm ci
npm run build:pre
npm test               # lint + усі тести
npm run test:coverage  # те саме з порогами покриття
```

## Реліз

1. У `develop` зібрано все, що йде у версію; `CHANGELOG.md` має секцію `[Unreleased]`.
2. Секцію перейменовують на номер версії, той самий номер ставлять у `package.json`.
3. `develop` зливають у `master`, на коміт ставлять тег `vX.Y.Z`.
4. `.github/workflows/release.yml` ще раз проганяє тести, перевіряє, що тег збігається з
   версією в `package.json`, і публікує образ у GHCR.

## Деплой

`.github/workflows/deploy.yml` запускається лише вручну: опублікований образ – це факт,
задеплоєний – рішення. Секрети лежать в оточенні `production`. Відкат – запуск того самого
workflow з попереднім тегом образу.
