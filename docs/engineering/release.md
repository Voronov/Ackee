# Готовність до релізу

Рішення про випуск спирається на критерії, записані заздалегідь. Цей чекліст заповнюють для
кожного реліз-кандидата. Заповнений чекліст зберігає команда поза репозиторієм, бо в ньому є
стан сервера.

Позначки: **Так**, **Ні**, **Частково**. Біля кожної позначки стоїть посилання на доказ: запуск
CI, звіт, картку. Критерій без доказу – це **Ні**.

## Рішення

| Рішення        | Коли                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| Go             | Усі обов'язкові критерії – **Так**                                                                                  |
| Conditional Go | Обов'язковий критерій не виконано, але є умова, строк і власник; ризик прийнято явно                                |
| No-Go          | Є відкритий дефект Blocker або Critical, втрата даних, витік між робочими просторами, або немає способу відкотитись |

Рішення приймає Product Owner (Сірко), Technical Lead (Пеняка) і QA (Громяк) дають свою оцінку.
Запис рішення містить дату, збірку, обґрунтування, умови й імена.

## Критерії

`*` – обов'язковий критерій.

### Функціональність

| Критерій                               | Як перевіряється          | Хто     |
| -------------------------------------- | ------------------------- | ------- |
| \* Усі картки Must цього релізу в Done | Дошка Trello              | Сірко   |
| \* Заявлені зміни є в CHANGELOG        | CHANGELOG проти злитих PR | Кравчук |

### Тести

| Критерій                                                            | Як перевіряється                                    | Хто    |
| ------------------------------------------------------------------- | --------------------------------------------------- | ------ |
| \* CI зелений на коміті тега: тести, покриття, audit, Docker        | Запуск `Test`                                       | Пеняка |
| \* Браузерні тести пройшли без повторів                             | Звіт `Browser tests`                                | Громяк |
| \* `smoke.sh` і `smoke-features.sh` на dev зелені                   | Запуск `Deploy`                                     | Громяк |
| \* Ручний прохід усіх розділів на dev                               | Чекліст QA                                          | Громяк |
| Звіти в межах NFR: p95 ≤ 300 мс на 10 млн записів під навантаженням | k6 на стенді, `docs/engineering/benchmark-stand.md` | Громяк |
| Контраст і доступність без критичних зауважень                      | axe                                                 | Громяк |

### Дефекти

| Критерій                                                       | Як перевіряється                  | Хто    |
| -------------------------------------------------------------- | --------------------------------- | ------ |
| \* Немає відкритих дефектів Blocker і Critical                 | Реєстр дефектів                   | Громяк |
| \* Кожне виправлення перевірено повторно                       | Реєстр дефектів, регресійний тест | Громяк |
| \* Відкриті дефекти Major мають рішення: виправити чи прийняти | Реєстр дефектів                   | Сірко  |

### Безпека і рев'ю

| Критерій                                                                      | Як перевіряється                                   | Хто    |
| ----------------------------------------------------------------------------- | -------------------------------------------------- | ------ |
| \* Кожна зміна пройшла рев'ю до злиття, а обхід `--admin` записано з причиною | PR, журнал                                         | Пеняка |
| \* Зміни з міткою 🔒 мають рев'ю безпеки                                      | PR                                                 | Пеняка |
| \* Немає необроблених сповіщень CodeQL рівня high і critical                  | Code scanning: виправлено або відхилено з причиною | Пеняка |
| \* `npm audit --omit=dev --audit-level=high` чистий                           | Крок `Dependency audit`                            | Пеняка |
| Секрети не потрапили в репозиторій                                            | Крок `Secrets`                                     | Пеняка |

### Дані і міграції

| Критерій                                                 | Як перевіряється                | Хто     |
| -------------------------------------------------------- | ------------------------------- | ------- |
| \* Міграції пройшли на dev і відомо, чи вони зворотні    | Журнал dev, опис PR             | Воронов |
| \* Є свіжий бекап live, перевірений пробним відновленням | Архів, `gzip -t` і відновлення в окрему базу | Воронов |
| \* Бекапи live робляться за розкладом                    | Розклад на сервері              | Воронов |
| Числа денних і годинних згорток збігаються               | Запит до бази                   | Воронов |

### Середовище і відкат

| Критерій                                   | Як перевіряється                          | Хто     |
| ------------------------------------------ | ----------------------------------------- | ------- |
| \* Конфігурація live звірена з dev         | Матриця конфігурацій                      | Воронов |
| \* Відкат відрепетирувано, час відомо      | Запуск `Deploy` зі старим тегом на стенді | Воронов |
| \* Деплой на live підтвердив інший учасник | Environment `live`                        | Пеняка  |
| На сервері є запас диска і пам'яті         | `df`, `free`, Grafana                     | Воронов |
